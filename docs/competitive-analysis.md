## Protocol and prior art

The current dated revision uses per-request protocol metadata and supports capability discovery. The SDK v2 stable line implements it. Current stdio signals cancellation with a notification. Streamable HTTP closes the request response stream. Earlier session-based versions used initialization and explicit cancellation notifications, and a disconnect could permit stream resumption. A tool annotation is a hint. Application authors own deduplication and the meaning of an authoritative state record. [Versioning](https://modelcontextprotocol.io/specification/versioning), [current bindings](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [legacy transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [SDK](https://github.com/modelcontextprotocol/typescript-sdk), [tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools).

Issue 3394 already compares guarded and unguarded operations following response loss. SEP-3182 proposed request idempotency and its PR was closed without merging. This kit uses an ordinary tool argument for application identity. It defines no protocol field. [Issue 3394](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/3394), [PR 3182](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3182).

## Adoption risks and useful overlap

Teams already using Rig may reasonably prefer another verifier in their existing suite. An independent state exporter costs more to integrate than another MCP call. Its credibility depends on whether it observes the real effect boundary and can identify terminal attempts. Cross-language ledger examples and a small shared corpus could make that investment reusable. A finite run provides evidence for one schedule. Publishing passing fixtures as a universal guarantee would undermine that evidence.

## Adversarial re-check

Rig's relay correlates the outgoing tool call with its JSON-RPC ID and intercepts the matching reply before its MCP client receives it. Its runner retries eligible infrastructure failures and can run another tool for verification. This kit suppresses an already decoded SDK response at the application boundary. Its defensible difference is the built-in out-of-band observer, the pre-retry receipt check, per-attempt terminal evidence and an explicit inconclusive verdict. A Rig verification tool can read the same underlying database; independent business truth is available to either project if the operator supplies it. The pinned comparison supports a difference in supplied workflow, without establishing market uniqueness.
