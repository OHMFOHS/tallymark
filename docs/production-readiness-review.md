# Production-readiness review

**Decision, 2026-11-21.** Reject 0.1.0 as a CI execution-safety gate. The review reproduced live false passes and an evidence-free saved pass. Use the corrected 0.2.0 candidate for controlled, opt-in experiments with a trusted exporter. Broader release confidence still depends on hosted CI and validating the exporter at a real downstream effect boundary.

The baseline was the local 0.1.0 archive with SHA-256 `7637fbb5ce9b186ad4655d9670a5fe872ba880c125fea6545b8db3558113e4b7`. The repository had no commit or remote. The review covered source, fixtures, tests, SDK transport implementation, examples, schemas, lockfile, package contents, documentation, templates and workflow. A separately written MCP server implements the business behavior used for the counterexamples. It shares the official SDK and does not import the payment-book implementation. Five of the first six new checks failed against the original implementation. The original crash-after-commit control already stopped dispatch. Additional checks used the installed baseline distribution.

**Severity.** Critical denotes a live green result that can conceal the exact retry hazard being tested. High denotes wrong CI evidence, a consequential permission or distribution boundary, or material supply-chain exposure. Medium and low include operational constraints and narrower defects. Dependency publisher ratings are recorded separately.

## Verification and migration

Run from the repository root with Node.js 22.12+ and pnpm 9.15.0. The named checks above are Vitest test-name filters. For example, after building, run `pnpm exec vitest run tests/integration/review.test.ts -t "terminal acknowledgements"`. The HTTP cases bind only ephemeral loopback ports.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm lint
pnpm format:check
pnpm test
pnpm test:package
pnpm audit --prod
pnpm audit
```

The YAML format remains v1. Report and scenario evidence are v2. External exporters must carry the attempt metadata through the effect boundary and publish the complete terminal ID set. Timeout cases also require cancellation telemetry for PASS. Existing count-only exporters remain readable and yield INCONCLUSIVE. Existing stdio invocations require the extra executable permission. Saved v1 passes require a rerun. [Observer example and migration details](contract-spec.md)
